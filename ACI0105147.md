It suspends the SpreadJS calc service before the command, and resumes it after with `Utils.spread.resumeCalcService(false)`.- When resumed, SpreadJS `CalcService.resume(recalcAll, skipDirtyVolatile)` re-evaluates the dirty volatile cells (`NOW()`, `TODAY()`, `RAND()`, `OFFSET()`...) unless `skipDirtyVolatile` is true. `resumeCalcService` calls it without that flag.- `VP EXPORT DOCUMENT` runs two commands, `get-sheet-count` then `export-excel`, so `NOW()` gets new values twice: once in the area and once in the exported file.- Exporting from the ribbon doesn't go through `runCommand`. SpreadJS itself uses `resume(false, true)` when serializing (`toJSON`), so volatile cells keep their values. That's the difference QA saw. It already happened before SpreadJS 18.### FixIn the `finally` of `runCommand`, commands that only read the document (name starting with `get-` or `export-`) resume the calc service without recomputing volatile cells:```jsUtils.spread.getCalcService().resume(false, true /* skipDirtyVolatile */);```- Other commands keep `resumeCalcService(false)`: a command that changes the document must still recompute.- **Minification:** `getCalcService` and `resume` are public SpreadJS API and keep their names in `gc.spread.sheets.all.min.js`, unlike private `_xxx` names, so this works with the production files.- Only `Resources/4dviewpro.js` changes: the `finally` block and a new helper, `_vp_isReadOnlyCommand(action)`.### PatchApply on main with:```shtr '\r' '\n' < ACI0105147.md | awk '/^```diff$/{p=1;next} /^```$/{p=0} p' | git apply``````diffdiff --git a/Resources/4dviewpro.js b/Resources/4dviewpro.jsindex e37892d..74bb9e7 100644--- a/Resources/4dviewpro.js+++ b/Resources/4dviewpro.js@@ -50,12 +50,26 @@ function runCommand(action, params = undefined) {     console.log(err.stack);     return { result: null, error: (typeof err === 'string') ?
