In 19R6 only Japanese was excluded, which is why 19.x works.- The first fix (commit bc4bce1, 2025-05-12) made this English exception configurable with `Utils.useDefaultEnglishCulture`, but set it to `true`, which keeps the 19R7 behaviour. That's why QA still reproduced it (Check again, build 296680).```js// Resources/scripts/init.js (unchanged, since bc4bce1)if ((vp_localizedFolder !== 'ja.lproj') // in japanese, use builtin japanese culture    && (!Utils.useDefaultEnglishCulture || (vp_localizedFolder !== 'en.lproj'))) {    const culture = getCulture(obj);    ...    GC.Spread.Common.CultureManager.culture(lang);}```### FixSet `Utils.useDefaultEnglishCulture` to `false`. In English, the culture built from the 4D intl settings is then used, as for the other languages and as in 19R6. Japanese still uses the builtin culture.Only `Resources/scripts/utils.js` changes. The condition added to `init.js` by bc4bce1 stays, so the old behaviour can come back by setting the flag to `true`.### PatchApply on main with:```shtr '\r' '\n' < ACI0105529.md | awk '/^```diff$/{p=1;next} /^```$/{p=0} p' | git apply``````diffdiff --git a/Resources/scripts/utils.js b/Resources/scripts/utils.jsindex 9833d56..9290826 100644--- a/Resources/scripts/utils.js+++ b/Resources/scripts/utils.js@@ -915,8 +915,8 @@ Utils._getLongOperationTimeout = function () {     return (timeout) ? timeout : Utils.longOperationTimeout; }; -// Use default english culture (ACI0105529)-Utils.useDefaultEnglishCulture = true;+// In english, if true use SpreadJS builtin english culture instead of the system one from 4D intl (ACI0105529)+Utils.useDefaultEnglishCulture = false;  function vp_startLongOperation() {     vp_counter++;```### How to check- In 4D: English UI with the system in French (on Windows, an English 4D, or remove `fr.lproj`).
