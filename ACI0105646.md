It uses the styles found in the JSON: cell styles, row, column and sheet default styles, and named styles.- **Tables and conditional formats:** their styles are not stored in cell styles. Table themes give the header, banded rows, first and last column, and borders; conditional format rules give the back color, font, color, borders and number format. SpreadJS computes them only when painting (`Worksheet.getActualStyle`), so the picture ignored them.- "Cell styles" from the ribbon work because they are real cell styles in the JSON (NOTE of the bug).- **Empty table cells:** when no range is given, `vp_getCellRange` stops at the last cell with data, so the empty rows at the bottom of a table (still banded and bordered in the area) were not drawn.### FixThe idea: at export, ask SpreadJS for the final style of the cells covered by tables and conditional formats, and give the picture code only what differs from the plain style.1. **JS, export** (`Utils.addFormatedText` in `file.js`): for each sheet, `_addActualStyleInfo(sheetName)`:   - **cells:** collects the cells of all tables (`sheet.tables.all()`, `table.range()`) and of the conditional format rules (`conditionalFormats.getRules()`, `rule.ranges()`). Rules on whole rows or columns stop at the last cell with a value or in a table. Data bar and icon set rules are skipped: they paint inside the cell, they don't change its style.   - **comparison** (`_getActualStyleInfo`), two styles per cell:     - `getActualStyle(r, c, viewport, false, {ignoreCellStatesStyle: true})`: the full style, as painted;     - `getActualStyle(r, c, viewport, true, {isForFilter: true, doNotAddCache: true})`: the style without tables, pivot tables and conditional formats, which is what 4D already computes from the JSON.   - **stored differences:** `backColor` (for a pattern fill, its background color), `foreColor`, `font`, `textDecoration`, `hAlign`, `vAlign`, the 4 borders, and a number format set by a rule (as `formatInfo`, computed like the other cells).   - **storage:** the differences go in a new sheet key, `sheet.actualStyleInfo[row][col]`. SpreadJS `fromJSON` ignores unknown keys, so re-importing the document doesn't create cell styles, and the table and rules stay the source of truth.   - **error handling:** the whole step is in a `try/catch`, so it can never break an export.   - **minification:** only public API is used. The option names (`ignoreCellStatesStyle`, `isForFilter`, `doNotAddCache`) are strings, and they are present unchanged in `gc.spread.sheets.all.min.js`.2. **4D, `VP Convert to picture`:**   - reads `$sheets.actualStyleInfo`;   - for each cell that has an entry, calls `svg_parseStyle($actualStyle; $parsedStyle)` before the other styles. `svg_parseStyle` keeps the first value set, so the table or rule style has priority, as in SpreadJS;   - its `foreColor` also replaces the color coming from the number format, because SpreadJS already resolved it.3. **4D, `vp_getCellRange`:** without a range, it extends the sheet range to the tables, so the empty table cells are drawn. In this method `$biggestCol` holds rows and `$biggestRow` holds columns; the change keeps that naming.Files: `Resources/scripts/commands/file.js`, `Project/Sources/Methods/VP Convert to picture.4dm`, `Project/Sources/Methods/vp_getCellRange.4dm`.### PatchApplies alone on main, and also before or after the ACI0104847 patch (they touch neighbouring lines of the same files; both
